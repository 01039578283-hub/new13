## 본문에서 선택하는 방식

이 사이트의 상세 본문은 학습법 원고가 아니라 원자료의 등록 정보, 학년 표기 및 상담 시 확인할 사항을 설명하는 사실 안내문이다. 다른 홈페이지의 학습법 접미사를 그대로 가져오면 본문과 맞지 않으므로 사용하지 않았다.

1. 실제 `academy-main-article` 안의 과목별 학년값을 읽는다. FAQ·후기·탐색 메뉴·숨김 텍스트는 제목 근거에 사용하지 않는다.
2. 본문에 명시된 모든 중간 학년이 있을 때만 연속 범위로 줄인다. 중간 학년 누락은 유지하며 영어와 수학의 학년 범위를 합치지 않는다.
3. 학년 표기는 모집 중이나 현재 수업 운영을 뜻하지 않으므로 `학년 표기`/`표기`라고 표현한다.
4. 상세 본문의 첫 안내문에 실제 등장하는 시간표, 반 구성, 교재, 비용 등의 확인 주제를 연결한다. 페이지명 해시나 무작위 순환으로 주제를 정하지 않는다.
5. 자료가 없다고 명시된 106개 상세 페이지는 `학년 자료 미기재`를 유지한다. 다른 과목의 학년을 대신 넣거나 수업 가능 여부를 추정하지 않는다.
6. 카테고리 9개는 각 페이지의 실제 소개 문단에서 확인되는 학습 안내 주제로 정한다.

결과: 전체 제목 3,348개는 서로 다르며, 접미사 조합은 509개다. 제목 길이는 27~49자다. 실제 정보가 같은 페이지는 접미사가 같을 수 있으며, 문구의 인위적인 완전 중복 제거보다 본문과의 일치를 우선한다.

예: `명일동 고등 수학학원 | 고1·고2 학년 표기·개설·수업 방식 확인`

## 재현·검증

PowerShell에서 프로젝트 폴더로 이동한 뒤 다음을 실행한다. 검증 과정에서 기존 사용자 Python 캐시 파일을 바꾸지 않도록 설정한다.

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$env:PYTHONDONTWRITEBYTECODE = '1'
python -m unittest discover -s tools -p test_title_suffixes.py -v
python tools/personalize_title_suffixes.py --check
python tools/verify_title_release.py
python tools/verify_title_release.py --public
```

본문이 의도적으로 바뀐 다음 제목을 다시 생성할 때만 `personalize_title_suffixes.py --write`를 사용한다. 기존 본문이 바뀌면 고정 기준 커밋 비교가 실패하도록 설계되어 있으므로 기준을 무조건 갱신하지 말고 실제 본문 변경부터 검토한다.

- 단위/회귀 검사 27개 통과.
- 로컬 타이틀 3,348개, 고정 공개본 대비 제목 외 변경 없음 확인.
- 지역 상세 3,339개 목차의 26,712개 앵커 구조 유지.
- 기존 목차 생성기의 `--check`는 작업 전부터 371개 페이지를 다시 포맷하려 한다. 이번 작업에서는 그 생성기를 실행해 본문을 다시 쓰지 않았으며, 현재 HTML에 대한 `validate_page` 구조 검증만 사용했다.

`tools/reports/title-suffix-audit.json`에 페이지별 전후 제목, 본문 근거와 보존 해시가 있다. 로컬 검증 보고서는 Git에 저장하고 초기 작업 상태·공개 HTTP 검사·실제 배포 영수증은 같은 폴더의 무시된 보고서로 보관한다. 전체 `tools/`는 Vercel 공개 파일에서 제외한다.

작업 시작 시 로컬 HEAD/원격 main은 `f8a161d3ebc5081c6e8f5f5a54c61ef424b6b27d`였지만, 실제 공개된 최신 화면은 그 후속 커밋 `b6804d601c4d0f0dc03b54c01815a39542460fa5`와 일치했다.

최종 Git SHA, Vercel deployment ID, 공개 도메인 확인 결과는 배포 후 `tools/reports/title-suffix-release.json`에 기록한다. 공개 완료 판단은 GitHub 푸시 성공뿐 아니라 정확한 Git SHA의 Vercel READY 상태와 실제 도메인 HTTP 제목 확인을 모두 기준으로 한다.
